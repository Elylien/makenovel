# 第三轮：脚本校验、节点身份与 Windows 样片

日期：2026-10-07。项目版本 0.0.3；WebGAL / Terre 仍锁定 4.6.5 的既定提交，未升级依赖。第二轮结果保留为历史记录，本页仅记录本轮实际完成的范围。

## 本轮实现

- 前后端复用纯 TypeScript 场景分析器，提供错误位置、原始源码区间、已知语句与高级源码分类。脚本错误和新增/改写的未审查高级源码在落盘事务之前被拒绝；旧接口覆盖场景文件必须使用带版本的保存入口。
- Monaco 显示诊断并可跳转；错误草稿保留在标签页。预览要求当前作品的已打开文档已保存且检查通过，其他作品的文档不再误阻止当前作品。
- 节点身份采用句尾注释，兼容已有独立标记。登记不增加物理行或原生语句数量；新增、复制产生新身份，移动保留身份。图形修改只改目标片段，保留其他参数、注释、BOM 与换行。
- 未知前缀可能是角色名或扩展指令，因此保留为高级源码；作者可明确选择“确认为角色对白”。复杂或歧义的编辑拒绝自动改写，保留源码入口。
- 修复 Windows ASAR 中原生 Steam 模块旁置问题，新增冻结版本的开发包导出及验证入口。实际 Windows GUI 结果详见 [独立导出记录](2026-10-07-windows-export.md)。

## 实际编辑器操作

在独立测试作品 `makenovel-round3` 中完成以下操作：

1. 载入包含 BOM、CRLF、旧身份标记和未知指令的场景；保留未知指令的原文。
2. 明确把角色对白转成 `say`，保留旧 ID 与作者注释；登记已知节点，修改对白并保存。
3. 复制一段对白后单独修改副本，原段不变；通过键盘拖动将副本向上移动，身份不变。
4. 在源码末尾输入 `wait:not-a-number;` 并尝试保存，界面定位第 10 行错误。草稿保留，磁盘 SHA256 前后均为 `c1029804c3b739d23417029b64f45e2c2a81300129d2e643b4146f28c5e4bad6`。
5. 修正为 `wait:100;`，并主动注释测试用未知指令后保存；界面显示“已保存 / 核心语法检查通过”。
6. 刷新页面确认对白、身份与顺序保持。图形模式新增普通对白自动得到独立 ID，编辑并保存成功。
7. 同一页面依次切换含高级源码的第二轮作品与第三轮作品；第三轮作品没有被另一个作品误暂停预览。

证据在 `local/round3/editor-invalid-draft.png`、`invalid-draft-check.json`、`editor-ready.png`。截图展示的是开发工具界面，不是最终美术或交互设计。

最终文件字节检查确认 BOM 保留、10 个 CRLF、0 个独立 LF，旧 ID、新增 ID 与作者双空格尾注释均保留。原始结果在 `local/round3/final-source-check.json`。补丁重放最终树与开发树均为 `00be9825e28de33ef40b8e10bd2b7642fdfe9b35`，结果在 `local/round3/product-patch-replay.json`。

## 范围与未完成项

当前分析器覆盖锁定原生语法的关键结构，不是完整语言编译器。资源存在性、变量运行值、所有表达式词法、扩展插件和整个工程的预检尚未覆盖；仅检查已打开文档的预览门禁也不等于直接运行或导出时的全工程校验。首次导入/新建文件允许保留原文，不能据此声称所有外部写入均已校验。

直接位于首条命令之前的 BOM 会影响原生解析，保留其真实行为并提示高级源码；BOM 后先放注释的测试场景通过。复杂多行和歧义参数仍需源码编辑。跨独立作者注释移动可能被拒绝，以免自动改变注释所属关系。

身份尚未用于旧玩家存档、收藏和历史迁移。跨窗口草稿持久化、项目级 Undo/Redo、资源管理与音频矩阵仍需后续工作。JSON/模板编辑的统一保存事务也未完成。

Windows 样片验证了一次真实槽位保存与重启恢复，没有完成物理断网、干净机器、全存档边界、签名发布或 DPI 矩阵。1600×900 EXE 未观察到菜单裁切，不代表第二轮 1280×720 浏览器裁切已修复。

收尾时本地编辑器仅监听 `127.0.0.1:3001`，独立 WebGAL.exe 已正常关闭；全局作者目录未创建。用户提供的两份原始文档仍由 Git 忽略，未纳入提交。
