# 第十七轮：Windows 导出来源与正常重启恢复

日期：2026-10-27；版本 `0.0.17`。本轮沿锁定 Terre 的 `ManageGameService.exportGame(electron-windows)` 导出，没有修改游戏执行器、存档协议或 vendor 源码。当前 Windows 子项结果在本页登记，不沿用历史包的验收结论。

## 修改与边界

原导出器外层检查只覆盖已有的作品条目及部分入口，尚不能确认共享模板来自当前已审核构建，也不能拒绝最终包中的全部额外文件。本轮新增 `export-integrity.cjs`，在导出前绑定来源，复制完成后对最终 ASAR 校验：

- 无自带入口的作品先执行 `Sync-Runtime.ps1 -Action Check`，确认当前审核源码和构建收据，再核对实际共享模板的完整引擎文件集及摘要。
- 自带 `index.html` 的作品继续使用自己的引擎，报告为 `self-contained`，不附加共享运行时收据。两类引擎均须有 manifest；锁定上游对缺失 manifest 会写入非 JSON 的 `file not exist`，因此明确拒绝，没有补写伪清单。
- 比对缓存壳的 main/preload 与锁定源码，以及壳 public 的完整文件集。仅允许构建器省略锁定的空 `.gitkeep`，不忽略其他隐藏文件或非空占位文件。
- 校验最终复制产物的全部 public 文件、完整 game 文件集、主引擎文件、原生两次 manifest 替换和 Service Worker 移除。原生 JavaScript 替换字符串语义保持，包括空描述与美元符号。
- 结束前再次校验作者作品、共享模板和收据未变。失败保留诊断目录，不输出成功收据。原有目录防覆盖、隔离作者 profile 和原生库旁置保持。

这套检查不证明整个 Electron 二进制依赖供应链、签名、恶意并发篡改防护或发行质量。它验证声明范围内的来源与精确内容，原生导出器仍负责打包。

## 进程启动检查

`Verify-Package.ps1`对同包执行两次12秒启动。仅子进程使用系统最小PATH、Chromium死代理 `127.0.0.1:9` 并去掉隐式loopback绕过；无需PATH中的Node，非管理员用户。两次均加载游戏，file协议绕过编辑器同步。独立profile与GUI默认APPDATA profile分开。

隐藏启动未取得可关闭窗口句柄，两次均标为 `controlled-process-termination`，不是正常退出，也没有验证强杀时存档事务。原始报告的 `editorStopped:false` 表示脚本未执行停止操作，独立进程记录证明本项目服务本来就不存在。netlog未完整落盘；操作系统网络仍开启，不能声称全机离线。

## 真实 Windows 窗口

使用 Computer Use 的原生窗口截图、可访问性和输入操作，经 `file:///.../resources/app.asar/public/index.html` 正常标题进入游戏，没有注入运行时状态或使用作者跳句。首次启动后用户按Escape中断了Computer Use；当时停止操作，用户明确要求继续后在同一已启动窗口恢复验收。

1. READY两人物画面正常。进入动画章节，等待后推进STABLE，在稳定点快速保存，并保存空的普通槽1。普通槽显示 `2026/10/27 12:16:05` 与STABLE缩略图。
2. 推进CLOSED，两人物消失；快速读档恢复双人物及橙色人物的动画结束位置。
3. Alt+F4正常退出，独立查询确认该包全部进程为零，本项目编辑器入口进程及3000/3001监听也为零。
4. 启动同一个EXE，标题读档仍显示同一槽1。读取后恢复STABLE，双人物及橙色人物终态正确。
5. 流程图“动画章节”在重启后仍解锁，点击节点恢复同一稳定画面。“准备章节”仍锁定，属于已知单对白无后续安全提交的边界。
6. 再推进CLOSED，快速读档再次恢复STABLE，确认快档跨正常重启持久化。
7. 第二次Alt+F4正常退出，再次确认全部包进程和项目服务/端口为零，然后恢复编辑器。

尝试在八秒动画期间点击快存时，实际点击已发生在动画结束后，因此不授予“Windows有限演出中拒存”通过。这不改变第十六轮代码/浏览器门禁证据，但不能拿它代替Windows新验收。结果仅证明同一包、同一精确作品版本的稳定点恢复，不证明跨版本迁移或精确动画相位恢复。
