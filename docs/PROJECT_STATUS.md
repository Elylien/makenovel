## 本轮实现与已核实范围

- 图形/源码复用 SceneDocument 的场景历史，默认最多 100 步、2 MiB UTF-16 文本增量；连续输入合并，图形操作独立成步，保存保留历史。撤销/重做只改草稿，冲突仍阻止保存；历史导航触发图形控件同步。历史栈只在当前页面内存中保留。
- 浏览器 localStorage 保存按工作区、场景路径和每个文档实例 owner 隔离的副本；关闭标签页后明确选择恢复，不自动覆盖磁盘或其他窗口副本。本标签页 session 刷新恢复保留；旧 v1 session 仅作为待核对作品的手动候选。
- session 与 durable 存储分别尝试，容量/权限失败提示下载备份，不阻止编辑器加载，不自动淘汰其他副本。浏览器清理数据、换 origin/profile 或换工作区会影响可见副本；尚无项目文件系统恢复仓或跨设备同步。
- 保存请求增加工作区前置条件。后端捕获同一次事务的 root 和 workspaceId；旧页面不能在另一个工作区同名、同字节 revision 的文件上先写入再报错。真实 HTTP 回归 9/9，包括工作区身份稳定、跨 profile 拒绝且双方文件不变、读取中切换工作区拒绝返回错误归属快照。
- 本轮代码回归 **259 项通过**：后端 14 suites / 124 tests、共享文档 56、vault 10、消息 3、源码输入 12、图形输入 7、身份 28、源码实验 19。后两类输入测试执行生产事件处理逻辑并使用边界替身，不代替真实 Windows 中文候选输入。
- GUI 已验证图形中文填写后立即 Ctrl+S、保存后跨源码/图形撤销重做、源码粘贴后 Ctrl+Z/Y，以及两场景切换不串稿；撤销时磁盘 hash 不变。关闭真实浏览器标签后重新打开，先显示磁盘原文，手动选中副本恢复全句再保存；另一作品的同名场景原文和恢复列表保持隔离。
- 最终两个场景的 BOM、节点 ID 与 CRLF 保留，start 10 个 CRLF、chapter-two 2 个、无单独 LF。仅有 game 目录的新作品经 HTTP 读取的 25 个引擎文件全部匹配构建凭据，实际游戏存档菜单 fixed，1280×720 根画布 (0,0)、body 滚动 0。
