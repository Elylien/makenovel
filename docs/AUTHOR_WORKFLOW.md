# 作者操作流程

这份流程使用现有 Terre 编辑器。作品的原生脚本是权威数据，图形编辑、源码编辑和本地 AI 工具共享同一份场景；保存需要核对磁盘修订和工作区。

## 从空白场景开始

1. 在游戏列表点“新建游戏”，分别填写显示名称和独立目录名。不要复用已有作品目录。
2. 进入作品，在 `figure`、`background` 等资源目录中点“上传资源”，选择已有授权的本地文件，再点“上传”。上传完成只证明文件进入目录，仍需实际预览检查显示。
3. 进入 `scene` 目录，点“新建文件”，创建 `story.txt`。原生新游戏自带示例 `start.txt`；新场景可以从空白开始，示例不算作者已经完成的内容。
4. 双击空白场景，使用上方“普通对话”添加第一句，填角色名和台词，点“保存脚本”。图形新增语句会获得稳定节点身份。
5. 在右下切换“脚本编辑器”。保留已有节点标记，可以补充舞台、后续对白、标签和分支。图形编辑使用以下显式对白形式：

   ```text
   say:雨停了，书页上的字还没有干。 -speaker=林;
   say:那就等一阵风，故事不必赶路。 -speaker=羽;
   choose:去窗边:window|留在桌旁:desk;
   label:window;
   say:窗外亮起来了。 -speaker=羽;
   jumpLabel:finish;
   label:desk;
   say:我们把这一页读完。 -speaker=林;
   label:finish;
   end;
   ```

6. 保存后切回“图形编辑器”，继续微调台词、选择分支目标或使用对白旁的“舞台与声音”。后者只编辑本句前允许的局部命令，不推演整个故事的舞台状态。高级代码保留源码入口。
7. 对源码新增的语句点“登记节点身份”，检查并保存。身份和台词修订不同；不要拿行号或相同文字代替节点身份。
8. 将新作品的 `start.txt` 设置为 `changeScene:story.txt;`，保留需要的作者注释。只修改当前作品的入口，不修改共享模板或旧作品。
9. 关闭并重开已保存场景，核对台词、分支和身份。定稿后按 README 的 `game:seal` 登记版本，再从标题正常走完各条路线。

出现未保存草稿、输入错误或版本冲突时，先保留当前稿。AI 或其他窗口保存后，在编辑器点“检查磁盘版本”；如已有本地修改，下载草稿后再决定如何载入磁盘内容，不强制覆盖。

## 与本地 AI 工具接力

按 [AI 创作说明](AI_AUTHORING.md) 依次查询、生成提案、查看差异、校验和提交。提交后在图形界面人工微调并保存；AI 再读取新的 revision 才继续。旧提案应明确报冲突，不能自动覆盖人工修改。

本工具不执行剧情、不自动封存，也没有内置聊天或模型服务。新增素材存在性检查不等于图片解码、声音试听或路线运行通过。

## 中文输入验证记录

输入保护已经覆盖新建游戏名称/目录、手填分支标签、游戏名称、新建文件/目录和重命名的 Enter 入口。代码回归使用真实组件回调与模拟组合事件；中文文本粘贴和程序输入也不能充当真实系统输入法验收。

真实候选验证应逐项记录输入法、宿主、可见候选窗、按键及结果：选词 Enter 不能创建/提交/关闭；组合结束后的普通 Enter 才提交一次。同时核对 Escape、组合键、粘贴、撤销、切面板、保存和来源跳转。当前实测和未执行范围见 [第十九轮证据](evidence/2026-10-27-round19.md)。
