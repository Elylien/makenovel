# 第十轮导演删除与排序样片

独立新建用于已有舞台命令删除、相邻排序、注释保留和整批撤销的作品。复用 `integrations/stage-demo/generate.mjs` 的纯素材工厂，背景标识改为 `ROUND 10`；不运行旧生成器、不读取或覆盖旧作品。每次新建使用独立 `Game_key` 和 `projectId`。

```powershell
node integrations/director-structure-demo/generate.mjs --output .local/editor-profile/games/makenovel-round10
node integrations/game-manifest/cli.mjs verify --game .local/editor-profile/games/makenovel-round10
node --test integrations/director-structure-demo/director-structure-demo.test.mjs
```

目标父目录须已存在且为普通目录；任何已存在的目标都拒绝覆盖。作品沿用经过审查构建的共享引擎，四个 GUI 模板文本及许可取自锁定 WebGAL 提交。素材为原创 SVG 与 PCM 诊断音，没有商业图片、音乐或真人录音。运行时构建期间不要执行生成器、封存或测试，以免与 parser 产物重建冲突。

`start.txt` 共 19 行，首行含 UTF-8 BOM，全部行及末尾使用 CRLF。第 2–5 行建立日景、音量 28 的 BGM 与双角色；第 7 行的普通对白将较早来源与本句局部设置分开。第 17 行是导演操作目标，第 18 行是沿用结果的后继对白。

| 初始位置 | 内容与用途 |
| --- | --- |
| 第 8 行 | 独立作者注释；不能被舞台卡片跨越或顺带删除 |
| 第 9 行 | 已登记 `r10-night` 的夜景，含作者行内注释；删除命令后保留作者文字，背景来源回到第 2 行日景 |
| 第 10 行 | 未登记的本句 BGM，音量 41；删除后保留作者文字，来源回到第 3 行音量 28 |
| 第 11 行 | `wait:500 -nobreak` 等待屏障；不能跨越排序，等待和作者注释均须保留 |
| 第 12–13 行 | 相邻的左侧林常态和笑脸命令。常态未登记，笑脸为 `r10-smile`；两条均使用原生 `-next`，交换后可观察最终表情改变 |
| 第 14 行 | 带不透明作者文字的独立注释，阻止立绘跨到效果音旁 |
| 第 15–16 行 | 独立 legacy 身份 `r10-se` 与其效果音。删除命令应同时移除所属身份，但保留第 16 行的作者行内注释；第 14 行保持原位 |
| 第 17 行 R10-TARGET | 已登记的当前对白，用于打开面板、应用本批修改及一次撤销/重做 |
| 第 18 行 R10-AFTER | 没有自己的舞台命令，显示前句设置对后继对白的影响；效果音不解释为持续继承状态 |

`readonly.txt` 需在编辑器中明确打开，第 4 行 `R10-OPAQUE` 前有未知参数背景，第 6 行 `R10-COMMAND` 前有变量命令。这些语句是导演结构操作的边界；原文须保留，不提供可重排或可删除的舞台卡片。本场景不从主场景自动进入。

建议 GUI 验证顺序：先查看未修改状态与按钮边界；在第 17 行面板删除夜景并查看日景来源，再交换两条左侧立绘，删除 legacy 效果音；先取消以比对原始文件，再重新执行并一次应用。应用后保存、执行到本句及后继对白，核对日景、最终常态表情和未改变的右侧角色。一次撤销应恢复整批改动，一次重做应重现；取消、注释和身份必须结合源码原字节核对，画面不能代替源码证据。

生成收据 `director-structure-demo-receipt.json` 记录初始 manifest、作品身份、源码/config/模板哈希、操作目标和屏障位置。改稿之后须显式重新封存；生成收据不代表后续改稿内容或验收结论。作品、玩家数据和原始本地证据不提交 Git。

3 项测试使用真实锁定 parser、runtime `assetSetter`、共享身份模块和 manifest 工具，覆盖原生命令顺序与资产映射、较早来源、混合身份、legacy 绑定、BOM/CRLF/注释、独立身份和拒绝覆盖。删除/排序事务本身由导演核心测试验证；实际浏览器操作、画面、预览隔离、原生控件失焦和 IME 需单独验收。
